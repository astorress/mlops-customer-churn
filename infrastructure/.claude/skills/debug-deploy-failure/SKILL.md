# Debug infrastructure deploy failures

Prerequisites: run inside the `DataScienceInfrastructure` devcontainer with `.envs/config.env` loaded. Reproduce
locally first with `serverless print --stage <stage>` from the failing stack folder.

| Symptom                                                                               | Probable cause                                                                                                  | Fix                                                                                                                       |
| ------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------- |
| `NOTIFICATION_EMAILS is empty`                                                        | env var missing in `.envs/config.env` (or container not rebuilt after editing it)                               | set it, rebuild/reopen the container; resolver: `serverless/shared/email-subscriptions.js`                                |
| `Cannot resolve variable at "custom.developer"`                                       | `DEVELOPER` missing                                                                                             | set it in `.envs/config.env`                                                                                              |
| `... already exists` / `BucketAlreadyExists` on a bucket                              | name collision: another developer/account uses the same `DEVELOPER`, or a retained bucket from a previous stack | change `DEVELOPER` or delete the orphan bucket after checking its content                                                 |
| `The bucket you tried to delete is not empty` on remove                               | versioned buckets keep object versions                                                                          | empty the bucket including versions (Console → Empty) after confirming no project needs the data, then retry `sls remove` |
| Safeguard `allowed-regions` / `allowed-stages` error                                  | `AWS_DEFAULT_REGION` not `us-east-1`, or stage not `dev`, `test` or `prod`                                      | fix `../.envs/aws.env` or the `--stage` flag                                                                              |
| `studio`: `Cannot resolve variable ... ssm:/data-science-common-infrastructure/...`   | `common` not deployed in this account                                                                           | deploy `common` first (`README.md` → Deployment)                                                                          |
| `studio`: `Cannot resolve variable ... ssm:/SLS/data-science-cloud-formation-vpc/...` | VPC stack not deployed in this account, or `DEPLOY_APP` differs from `data-science`                             | `npm run deploy-vpc:<stage>`; check `DEPLOY_APP` in `.docker/docker-compose.yml`                                          |
| `studio`: domain creation fails on a subnet / AZ                                      | `zones: auto-discover` placed subnets in an AZ Studio may not support (unverified)                              | check the failing subnet's AZ ID; see `.claude/rules/deployment.md` → First-run gotchas                                   |
| VPC deploy: `Value not found at "env" source ... LIBCFNVPC_DB_PORT`                   | library always resolves the DB port                                                                             | set `LIBCFNVPC_DB_PORT=5432` (`.claude/rules/dependencies.md`)                                                            |
| VPC deploy creates a NAT gateway / EIP                                                | `LIBCFNVPC_VPC_CREATE_NAT_GATEWAY` unset (library default = 1)                                                  | set it to `false` and redeploy                                                                                            |
| `deploy-vpc`: `No such file or directory` for `customlib/...`                         | library not cloned (entrypoint didn't run or the GitLab SSH key secret is missing)                              | reopen the devcontainer in VS Code; check `~/.ssh/gitlab` on the host                                                     |
| VPC remove fails with `DependencyViolation`                                           | Studio's EFS mount targets / security groups still in the subnets                                               | delete them after removing `studio` (`README.md` → Remove)                                                                |
| `studio`: update requires replacement of `StudioDomain`                               | changed `VpcId`, `SubnetIds`, `AuthMode` or `DomainName`                                                        | escalate — replacement deletes user homes                                                                                 |
| A project fails with unresolved `${ssm:/data-science-common-infrastructure/X}`        | `common` missing in that account/region, or `X` renamed in `serverless/common/ssm.yml`                          | deploy `common`, or align names (see `.claude/rules/integrations.md`)                                                     |
| Notifications never arrive                                                            | subscription `PendingConfirmation`, or topic policy changed                                                     | `aws sns list-subscriptions-by-topic --topic-arn <arn>`; check `sns.yml` policy principals                                |
| Project ingestion never starts after a raw upload                                     | data lake `EventBridgeEnabled` off                                                                              | check `s3.yml` → `NotificationConfiguration`                                                                              |

If the error is a CloudFormation `UPDATE_ROLLBACK_FAILED`, read the stack events in the console before retrying —
retrying blindly can leave buckets orphaned.
